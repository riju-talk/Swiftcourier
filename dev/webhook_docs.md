## Overview

IdiotShip sends outgoing webhooks to notify your server in real time whenever a shipment status changes or a significant account event occurs. This eliminates the need to poll the tracking API repeatedly.

**How it works:**

1. You register a publicly accessible HTTPS endpoint (URL) in your IdiotShip dashboard.
2. IdiotShip signs every webhook payload with a secret key unique to your account.
3. When an event occurs, IdiotShip sends an HTTP `POST` request to your endpoint with a JSON payload.
4. Your server must respond with HTTP `200 OK` within **10 seconds** to acknowledge receipt.

## Setup & Registration

### Via Dashboard

Go to **Settings → Webhooks → Add Endpoint** in your IdiotShip dashboard.

| Field            | Required | Description                                                      |
|------------------|----------|------------------------------------------------------------------|
| Endpoint URL     | Yes      | Your publicly accessible HTTPS URL. e.g. `https://mystore.com/webhooks/idiotship` |
| Secret Key       | Auto     | Auto-generated by IdiotShip. Used to sign payloads (keep it private) |
| Events           | Yes      | Select which events to subscribe to (or subscribe to all)        |
| Active           | Yes      | Toggle to enable/disable the webhook endpoint                    |

### Via API

```
POST /api/webhooks
```

**Authorization:** Bearer Token

**Body**

```json
{
  "url": "https://mystore.com/webhooks/idiotship",
  "events": [
    "shipment.delivered",
    "shipment.ndr",
    "shipment.rto_initiated",
    "payment.cod_remittance_paid"
  ],
  "active": true
}
```

**Response — Success**

```json
{
  "status": true,
  "data": {
    "id": 12,
    "url": "https://mystore.com/webhooks/idiotship",
    "secret": "whsec_a3f8d92b1c4e76f0a1b2c3d4e5f6a7b8",
    "events": [
      "shipment.delivered",
      "shipment.ndr",
      "shipment.rto_initiated",
      "payment.cod_remittance_paid"
    ],
    "active": true,
    "created_at": "2026-05-12T10:00:00Z"
  }
}
```

> **Important:** Store the `secret` immediately. It will not be shown again in full. You can rotate it from the dashboard at any time.

## Security & Verification

Every webhook request sent by IdiotShip includes a signature header. You **must** verify this signature before processing the payload to ensure the request genuinely came from IdiotShip and was not tampered with.

### Signature Header

```
X-IdiotShip-Signature: sha256=<hex_digest>
```

### Verification Steps

1. Extract the raw request body (as bytes — do **not** parse JSON first).
2. Compute an HMAC-SHA256 digest using your webhook `secret` as the key and the raw body as the message.
3. Compare the computed digest against the value in `X-IdiotShip-Signature` (after the `sha256=` prefix).
4. If they match, the webhook is authentic. If not, discard it and return `401`.

### Code Examples

**Python**

```python
import hmac
import hashlib

def verify_shipzee_webhook(raw_body: bytes, secret: str, signature_header: str) -> bool:
    expected = hmac.new(
        secret.encode("utf-8"),
        raw_body,
        hashlib.sha256
    ).hexdigest()

    received = signature_header.replace("sha256=", "")
    return hmac.compare_digest(expected, received)
```

**Node.js**

```javascript
const crypto = require("crypto");

function verifyShipZeeWebhook(rawBody, secret, signatureHeader) {
  const expected = crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");

  const received = signatureHeader.replace("sha256=", "");
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(received)
  );
}
```

**PHP**

```php
function verifyShipZeeWebhook(string $rawBody, string $secret, string $signatureHeader): bool {
    $expected = hash_hmac('sha256', $rawBody, $secret);
    $received = str_replace('sha256=', '', $signatureHeader);
    return hash_equals($expected, $received);
}
```

> Always use a **timing-safe comparison** function (e.g. `hmac.compare_digest` in Python, `timingSafeEqual` in Node.js, `hash_equals` in PHP) to prevent timing attacks.

## Delivery & Retry Policy

| Property         | Value                                                      |
|------------------|------------------------------------------------------------|
| Method           | `HTTP POST`                                                |
| Timeout          | 10 seconds per attempt                                     |
| Success criteria | HTTP response status `200–299`                             |
| Retry schedule   | 5 min → 30 min → 2 hrs → 6 hrs → 24 hrs (5 attempts total)|
| Max retries      | 5                                                          |
| After all retries fail | Event is marked `failed` in the webhook log. You can manually replay it from the dashboard. |

**Additional Headers sent with every request**

| Header                  | Description                                          |
|-------------------------|------------------------------------------------------|
| `Content-Type`          | `application/json`                                   |
| `X-IdiotShip-Signature`   | HMAC-SHA256 signature (see above)                    |
| `X-IdiotShip-Event`       | Event name e.g. `shipment.delivered`                 |
| `X-IdiotShip-Delivery-ID` | Unique UUID for this delivery attempt (for idempotency) |
| `X-IdiotShip-Timestamp`   | Unix timestamp of when the event was generated       |
| `User-Agent`            | `IdiotShip-Webhook/1.0`                                |

## Webhook Events

All events share the same outer envelope. The `data` object varies by event type.

### Envelope Structure

```json
{
  "event": "<event.name>",
  "delivery_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "timestamp": "2026-05-12T10:30:00Z",
  "shipzee_code": "SZC265255",
  "data": { }
}
```

| Field        | Type   | Description                                              |
|--------------|--------|----------------------------------------------------------|
| event        | string | Event name (see events below)                            |
| delivery_id  | string | UUID unique to this delivery attempt. Use for idempotency|
| timestamp    | string | ISO 8601 datetime when the event was triggered           |
| shipzee_code | string | Your IdiotShip merchant code                               |
| data         | object | Event-specific payload                                   |

## Webhook Payload Structure

### Common Fields in `data` (present on all shipment events)

| Field        | Type   | Description                                      |
|--------------|--------|--------------------------------------------------|
| order_id     | string | IdiotShip internal order ID (e.g. `SZ10042`)       |
| order_number | string | Your original order reference (e.g. `#1001`)     |
| awb_number   | string | Courier AWB / tracking number                    |
| courier_name | string | Name of the courier partner                      |
| status       | string | Current order status (see status table below)    |

### Full Order Status Reference

| Status               | Description              | Triggers RTO Charges |
|----------------------|--------------------------|----------------------|
| ready_to_ship        | Shipment booked, not yet dispatched | No |
| pending_pickup       | Awaiting courier pickup  | No                   |
| in_transit           | Picked up, in transit    | No                   |
| out_for_delivery     | Out for delivery         | No                   |
| delivered            | Delivered to consignee   | No                   |
| ndr                  | Delivery attempt failed  | No                   |
| exception            | Courier exception raised | No                   |
| rto                  | RTO initiated            | **Yes**              |
| rto_in_transit       | Returning to origin      | No                   |
| rto_delivered        | Returned to your hub     | No                   |
| cancelled            | Shipment cancelled       | No                   |
| lost                 | Shipment lost in transit | No                   |
| damaged              | Shipment damaged         | No                   |

## Responding to Webhooks

Your endpoint must respond within **10 seconds** with an HTTP `2xx` status code.

**Minimal valid response**

```
HTTP/1.1 200 OK
```

No response body is required. IdiotShip ignores the body entirely.

**Idempotency**

IdiotShip may deliver the same event more than once (due to retries). Use the `delivery_id` field to deduplicate events on your side before processing.

```python
# Example: idempotency check before processing
if already_processed(event["delivery_id"]):
    return HttpResponse(status=200)  # acknowledge but skip

process_event(event)
mark_as_processed(event["delivery_id"])
```

**Do not do heavy processing synchronously.** Acknowledge the webhook immediately with `200 OK`, then enqueue the payload for async processing (via Celery, Redis Queue, etc.).

```python
# Recommended pattern (Django example)
def shipzee_webhook(request):
    # 1. Verify signature first
    if not verify_signature(request):
        return HttpResponse(status=401)

    # 2. Acknowledge immediately
    payload = json.loads(request.body)

    # 3. Enqueue for async processing
    process_shipzee_event.delay(payload)

    return HttpResponse(status=200)
```

```json

  "status": true,
  "message": "Test event dispatched to https://mystore.com/webhooks/idiotship",
  "delivery_id": "test_a1b2c3d4-e5f6-7890-abcd-ef1234567890"
```
